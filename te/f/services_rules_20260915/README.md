# Правила услуг — версия 2 от 15.09.2026

В этой версии сохранены прежние обязательные поля из `config.php`. Новые пункты ТЗ заполняются строками в «Описании проблемы»; отдельные поля `field_supply_*` из первого пробного комплекта не добавляются.

Для 66 целевых услуг справа показывается таблица требований. Блок «Исполнитель задачи должен:» занимает место «Общих правил» и виден целиком. При выборе другой услуги либо возврате к выбору раздела восстанавливаются исходные «Общие правила» с прежней разметкой. Содержимое исходного `template.php` не переписывается.

Предзаполненное описание и полный текст правил попадают в задачу. Это обычный текст описания, не placeholder. Правила добавляются сервером независимо от правого блока и не исчезают после постановки задачи.

## Установка

Каталог компонента:

```text
/home/bitrix/www/local/components/kuratovru/services.main/
```

Сохраните текущие `class.php`, JavaScript активного шаблона и ранее добавленные файлы правил в Git или резервную копию вне публичного каталога. Затем установите комплект в таком порядке:

| Файл в архиве | Куда установить |
| --- | --- |
| `component/service_rules.php` | Добавить или обновить рядом с `class.php` |
| `component/service_rules.css` | Добавить или обновить рядом с `class.php` |
| `template/script.js` | Заменить JavaScript фактически используемого шаблона `services.main` |
| `component/class.php` | Обновить файл компонента |

`config.php`, `template.php`, `TaskServiceBuilder.php` остаются прежними. Запускать файлы как команды в PHP-консоли не нужно.

Этот комплект полностью заменяет предыдущие варианты `service_task_rules.php`, `service_requirements.php` и первую версию `service_rules.php`. Не объединяйте старую вставку добавления текста с новой: используйте один вариант `class.php` и соответствующий ему JavaScript из этого архива. Старые файлы конфигурации можно убрать после удаления их подключений.

Выполните Ctrl + F5. Если на портале объединяется или кэшируется JS, обновите соответствующий ресурс. Не отправляйте заявки из старой, уже открытой формы до обновления страницы. Перед обновлением сохраните введённые сведения.

Готовые файлы основаны на исходниках, ранее присланных 14.09.2026; их контрольные суммы приведены в `source_sha256.txt`. Если серверные файлы с тех пор менялись, перенесите изменения по `changes.diff`. Для перехода с предыдущего комплекта с правыми подсказками добавлен `changes_from_previous.diff`.

## Что обязательно заполнить

Прежние поля и их обязательность определяет существующий `config.php`: например, номер проекта и номер заказа на производство. Их штатная проверка сохраняется в браузере. Исправлено сравнение ID разделов и услуг, чтобы числовые ID в конфигурации корректно сопоставлялись со строками из HTML и AJAX.

Для новых пунктов браузер и сервер проверяют строки исходного описания:

| Строка | Условие |
| --- | --- |
| Наименование | Всегда |
| Количество | Всегда; свободный текст, например `10 шт.` |
| Основные характеристики | Всегда; допускаются несколько строк |
| Абсолютно новая продукция | Всегда; `Да` или `Нет`, без заранее выбранного ответа |
| Направление деятельности | При ответе `Да` на предыдущий пункт |
| Особые условия | Всегда; если условий нет, нужно самостоятельно указать `Нет` |
| Вид работы (аутсорсинг) | Для услуг `242320`, `242324`; для `243117` после включения ВЭД |
| Дополнительные сведения | По необходимости |

Пользователь заполняет текст после двоеточий и сохраняет заголовки строк. Ответ можно перенести на следующие строки. Пустой шаблон, строки из пробелов, простые заглушки вроде `...`, повторяющиеся заголовки и неверный ответ вместо `Да/Нет` отклоняются. Проверяется заполнение и структура, а не достоверность или достаточность содержания.

Новое серверное правило применяется только к перечисленным услугам. При ошибке обработка завершается до вложений и построителя задачи. Значения прежних допполей добавляются после проверки исходного описания; они не могут случайно заполнить пустую строку шаблона.

## Переходы и черновики

- При выборе целевой услуги появляется шаблон. Если у услуги уже есть `START_TEXT`, он сохраняется, добавляются только отсутствующие заголовки шаблона.
- Введённый текст сохраняется отдельно для каждой выбранной услуги в памяти открытой страницы. При возврате он восстанавливается; намеренно очищенное описание остаётся пустым.
- При смене раздела инструкция исполнителю сразу скрывается и возвращаются исходные общие правила, в том числе пока ожидается AJAX-ответ.
- Повторная попытка отправки не дописывает поля в textarea и не накапливает их в описании. Это не защита от повторного создания задачи при неизвестном результате сетевого запроса.
- Черновики не переживают обновление или закрытие страницы. Значения отдельных прежних допполей при пересоздании формы ведут себя как прежде; эта доработка сохраняет черновики именно описания.

## Охват и настройки

В `service_rules.php` для `APP_ENV=prod`:

```php
'enabled' => true,
'include_ved' => false,
```

Охват: прежние 66 услуг снабжения. Консультации, внутренние претензии и Таткуз не включены. ВЭД остаётся выключенным; после подтверждения охвата его пяти услуг включается `include_ved`. Для `dev` нужны отдельные подтверждённые ID, автоматического переноса ID production нет.

`sections` содержит исходный текст ТЗ для правой колонки и задачи. Секция с `placement => 'general'` заменяет общие правила. `description_fields` определяет строки описания, условия проверки и пояснения в таблице. Если меняется состав требований, согласованно обновите и `sections`, и `description_fields`.

Для отключения измените `enabled` на `false` и обновите форму. Не удаляйте `service_rules.php`, пока `class.php` его подключает. Полный откат: восстановить прежние `class.php` и `script.js`, затем убрать неиспользуемые файлы правил.

Проверены синтаксис JavaScript, синтаксис PHP и серверная проверка в локальном PHP 8.5.10 (WASM). Компонент проверялся с заглушками интерфейсов Bitrix: обработчики портала и построитель не запускались. В локальном Chromium проверены переходы, восстановление исходной разметки правил, черновики, `START_TEXT`, поля из конфигурации, повторная отправка и узкая колонка. Обнаруженное обрезание описания при изменении ширины исправлено пересчётом высоты.

Кнопка «Проверить заполнение» работает только с локальной заглушкой. `preview.png` и `preview_mobile.png` показывают заполненный пример.
