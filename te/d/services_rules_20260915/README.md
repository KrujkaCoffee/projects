# Правила услуг — версия 3 от 15.09.2026

Новые сведения заполняются отдельными инпутами, списком и многострочными полями. Их определения находятся в `fields` файла `service_rules.php`. Общий конструктор строит как прежние поля из `config.php`, так и новые. Сервер по своей конфигурации проверяет значения и добавляет их в описание задачи. Разбора заголовков и предзаполненного текстового шаблона больше нет.

Прежние поля из `config.php`, таблица требований справа, инструкция исполнителю вместо «Общих правил» и восстановление исходных правил при возврате сохранены. «Описание проблемы» остаётся свободным текстом для пояснений.

## Установка

Каталог компонента:

```text
/home/bitrix/www/local/components/kuratovru/services.main/
```

Сохраните актуальные файлы в Git или сделайте резервную копию вне публичного каталога. Устанавливайте комплект целиком, не смешивая файлы разных версий. На время замены файлов не отправляйте заявки из открытой формы.

| Файл в архиве | Действие |
| --- | --- |
| `component/service_rules.php` | Добавить или обновить рядом с `class.php` |
| `component/service_rules.css` | Добавить или обновить рядом с `class.php` |
| `template/script.js` | Обновить JavaScript фактически используемого шаблона |
| `component/class.php` | Обновить файл компонента |

`config.php`, `template.php` и `TaskServiceBuilder.php` менять не нужно. Выполнять содержимое файлов в PHP-консоли не требуется.

После установки выполните Ctrl + F5; при объединении или кэшировании JS обновите соответствующий ресурс портала. Предварительно сохраните введённые данные. Сервер отклоняет отправку целевой услуги, если версия схемы открытой формы не совпадает с текущей.

Комплект заменяет все предыдущие варианты доработки. Не добавляйте к нему старые вставки `service_task_rules.php` или `service_requirements.php`. Неиспользуемые файлы можно убрать после удаления их подключений.

`changes.diff` показывает изменения относительно первоначальных исходников от 14.09.2026. `changes_from_previous.diff` — переход с версии 2, где сведения вводились строками шаблона. Если серверные файлы менялись после выгрузки, перенесите изменения по diff. Контрольные суммы исходников приведены в `source_sha256.txt`, текущих файлов — в `checksums.sha256`.

## Какие поля появляются

| Поле | Тип | Обязательность |
| --- | --- | --- |
| Наименование | `text` | Всегда |
| Количество | `text` | Всегда; например, `10 шт.` |
| Основные характеристики | `textarea` | Всегда |
| Абсолютно новая продукция | `list`: Да / Нет | Всегда, без заранее выбранного ответа |
| Направление деятельности | `textarea` | Появляется и обязательно при выборе Да |
| Особые условия | `textarea` | Всегда; если условий нет, пользователь указывает Нет |
| Вид работы (аутсорсинг) | `textarea` | Только для услуг производственного аутсорсинга |

Прежние поля по-прежнему определяются `config.php`, включая номер проекта и номер заказа на производство. Их штатная проверка сохраняется в браузере. Для новых полей обязательность, допустимые значения списка и условия видимости проверяются также на сервере до вложений и построителя задачи.

Ошибки новых полей выводятся рядом с инпутом. Скрытое поле отключено, не отправляется браузером и не включается сервером в описание даже при ручной подстановке POST-параметра. Пустые строки, строки из Unicode-пробелов, массив вместо текста и неизвестный вариант списка отклоняются. Проверка не оценивает достоверность введённых сведений.

## Декларация поля

Пример уже включённого условного поля в `service_rules.php`:

```php
[
    'name' => 'field_supply_activity',
    'label' => 'Направление деятельности',
    'type' => 'textarea',
    'rows' => 2,
    'required' => true,
    'visible_if' => [
        'field' => 'field_supply_new_product',
        'equals' => 'Да',
    ],
    'condition_hint' => 'Для новой продукции',
    'hint' => 'Аспирация, металлообработка, запорная арматура и т.д.',
],
```

| Параметр | Назначение |
| --- | --- |
| `name` | Уникальное стабильное имя поля в DOM и POST; для новых полей не используйте случайный GUID |
| `label` | Подпись в форме, таблице требований и итоговом описании |
| `type` | Поддерживаются `text`, `textarea`, `list` |
| `required` | Обязательность, пока поле видимо |
| `values` | Варианты списка: пары `label` / `value` |
| `visible_if` | Показ при равенстве значения другого поля указанной строке |
| `condition_hint` | Пояснение условия в таблице справа |
| `outsource_only` | Ограничение поля списком услуг аутсорсинга на сервере |
| `hint`, `placeholder` | Подсказки; в описание задачи не подставляются |
| `rows`, `layout` | Высота textarea и ширина; `layout => 'wide'` занимает всю строку |

Добавление обычного поля поддерживаемого типа в `fields` не требует отдельной ветки JavaScript или ручного дописывания значения в задачу: отрисовка, проверка и сборка используют декларацию. При изменении состава или условий полей измените и `version`, чтобы уже открытые формы получили понятное требование обновления. Если меняются требования ТЗ, согласованно обновите текст в `sections`.

## Что получает задача

Сервер собирает описание в таком порядке:

1. Свободные пояснения из «Описания проблемы».
2. Значения прежних дополнительных полей.
3. «Сведения по заявке» — подписи и значения новых видимых полей.
4. Полный текст правил, включая обязанности исполнителя.

Пустые необязательные поля пропускаются. Значения новых полей передаются отдельно; названия и порядок сервер берёт из своей конфигурации. `TaskServiceBuilder` получает уже собранную строку через прежний `setDescription()`.

В `task_description_example.txt` приведён локально собранный пример. Это не описание созданной на портале задачи.

## Навигация, охват и отключение

Черновики свободного описания и новых полей сохраняются отдельно для каждой услуги в памяти открытой страницы. При переключении Да → Нет → Да значение направления деятельности восстанавливается. При смене услуги или раздела неиспользуемые новые поля удаляются из формы. Исходные общие правила возвращаются сразу, включая время ожидания AJAX-ответа. Собственный `START_TEXT` других услуг сохранён.

Черновики не переживают обновление или закрытие страницы. Значения прежних отдельных полей при пересоздании формы ведут себя как раньше. Повторная попытка отправки не дописывает значения в textarea; это не защита от повторного создания задачи при неизвестном результате сетевого запроса.

Для `APP_ENV=prod` включены прежние 66 услуг снабжения. Консультации, внутренние претензии и Таткуз не включены. ВЭД по-прежнему выключен через `include_ved => false`. После подтверждения охвата всех пяти услуг его можно включить. Аутсорсинг определяется ID `242320`, `242324`, а для ВЭД — `243117`. Для `dev` требуются свои подтверждённые ID.

Для отключения установите `enabled => false` в нужной среде и обновите форму. Не удаляйте `service_rules.php`, пока `class.php` его подключает. Полный откат — восстановить прежние `class.php` и `script.js`, затем убрать неиспользуемые файлы правил.
