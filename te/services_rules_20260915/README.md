# Правила услуг: показ справа и сохранение в задаче

Комплект от 15.09.2026 для `kuratovru:services.main`, по ТЗ от 11.09.2026.

## Результат

После выбора целевой услуги справа сохраняется существующее «Описание услуги» со сроком и режимом работы. Под ним появляются:

1. **Требования к заявке** — открытый список сведений, которые нужно указать.
2. **Вложения и ссылки** — правила подготовки материалов.
3. **Обратная связь** — условие закрытия некорректно поставленной задачи.
4. **Правила работы исполнителя** — раскрываемая инструкция.

Существующий блок «Общие правила» остаётся ниже. Текст ТЗ сохранён без изменения формулировок. Полная инструкция, включая закрытый в форме раздел исполнителя, добавляется в описание новой задачи на сервере.

Пользователь заполняет прежнее «Описание проблемы» и существующие поля. Новые обязательные поля из пробного комплекта не используются. Полноту сведений проверяет исполнитель; автоматического контроля пунктов инструкции, проверок контрагентов и закрытия задач здесь нет.

## Файлы для установки

Компонент:

```text
/home/bitrix/www/local/components/kuratovru/services.main/
```

| Файл в архиве | Действие |
| --- | --- |
| `component/service_rules.php` | Добавить в каталог компонента рядом с `class.php` |
| `component/service_rules.css` | Добавить туда же |
| `component/class.php` | Заменить `class.php` компонента либо перенести изменения по `changes.diff` |
| `template/script.js` | Заменить `script.js` фактически используемого шаблона `kuratovru:services.main` |

Файл `script.js` — тот, который ранее был предоставлен как `script(1).js`. Его точный каталог на сервере не подтверждён; папка `template` в архиве обозначает назначение файла и не является указанием создать такой каталог на сервере. Путь подключённого файла можно посмотреть в F12 → Network при загрузке страницы, если JavaScript не объединён в общий ресурс.

`config.php`, `template.php`, штатный `style.css`, `Service.php` и `TaskServiceBuilder.php` этим комплектом не заменяются. Существующие поля, выбор проекта, назначение исполнителей и расчёт срока остаются в исходном коде.

Файлы `README.md`, `changes.diff`, `mandatory_text.txt`, `source_sha256.txt`, `validation.md`, `preview.html` и изображения предназначены для просмотра комплекта, а не для установки в компонент.

## Порядок внедрения

1. Сохранить текущие `class.php` и `script.js` в Git либо вне публичного каталога сайта. Если после исходной выгрузки в них появлялись изменения, использовать `changes.diff`, а не перезаписывать их целиком.
2. Сначала положить в каталог компонента **`service_rules.php` и `service_rules.css`**.
3. Обновить **`script.js` активного шаблона**.
4. Обновить **`class.php` компонента**.
5. Обновить страницу с `Ctrl + F5`. При включённом объединении или кэшировании JS обновить соответствующий ресурс портала. Вкладки, открытые до установки, нужно перезагрузить, предварительно сохранив набранный текст.

Новый JavaScript совместим с исходным ответом компонента: до обновления `class.php` дополнительных правил просто не будет. Новый PHP не требует новых POST-полей. Пользователям нужна свежая версия JavaScript, чтобы увидеть правила справа.

После установки достаточно открыть форму, выбрать нужную услугу и раскрыть инструкцию исполнителю для проверки отображения. Создавать задачу для просмотра правил не нужно. Сам факт отправки на рабочем портале создаёт настоящую задачу обычным способом.

## Область применения

В `service_rules.php` включена ветка `prod`:

```php
'enabled' => true,
'include_ved' => false,
```

Правила применяются к ранее сопоставленным **66 услугам снабжения**: 51 — Пауэрз, 15 — Келаст. Список ID и комментарии к строкам ТЗ сохранены из предыдущего комплекта. Например, пиломатериалы Келаст — `257874`.

Консультации `244015`, `244014`, внутренние претензии `255216`, `255167` и услуги Таткуз `260968`, `260969` не подключены. При переключении на услугу вне списка новый блок исчезает; инструкция к её задаче не добавляется.

ВЭД остаётся выключенным: `243116`, `243117`, `243118`, `291448`, `313011`. После определения охвата `include_ved => true` подключает все пять, то есть всего получится 71 услуга.

Для `dev` правила выключены, списки ID пусты. Производственные ID в dev автоматически не переносятся. При неизвестном или отсутствующем `APP_ENV` новые правила также не применяются. Новая услуга внутри раздела не подключится автоматически: её ID нужно добавить в нужный список.

## Где редактировать текст

Единственный источник — массив `sections` в **`service_rules.php`**. В каждом разделе:

- `title` — заголовок в правой колонке;
- `kind` — оформление (`primary`, `standard`, `notice`, `details`);
- `text` — сама инструкция, общая для формы и задачи.

Сервер собирает `task_heading` и текст всех разделов в исходной последовательности. Заголовки оформления в задачу дополнительно не вставляются. Результат текущей сборки приведён в `mandatory_text.txt`.

В тексте правила строки `* ` отображаются как пункты списка, последующие строки `- ` — как вложенный список. Остальное показывается абзацами. HTML в новых правилах отображается как текст. Не нужно редактировать `PREVIEW_TEXT` 66 элементов инфоблока.

Схема обработки:

```text
service_rules.php → правый блок выбранной услуги
service_rules.php → дополнение $description → существующий TaskServiceBuilder
```

Общий текст передаётся браузеру один раз на ответ со списком услуг. ID выбранной услуги проверяется повторно на сервере; браузер не передаёт текст инструкции для записи в задачу. Полностью совпадающий блок повторно не добавляется. Старые задачи не изменяются.

## Если пробный комплект остался на тестовом сервере

Этот комплект подготовлен от исходных файлов, а не как дополнительная вставка поверх варианта с обязательными полями. Заменить оба файла: `class.php` и `script.js`, а также добавить новые PHP и CSS по порядку выше. После этого предыдущие `service_requirements.php` и `service_task_rules.php` данным кодом не используются. Старые вставки вручную в новый `class.php` переносить не нужно.

## Отключение и откат

В нужной ветке `service_rules.php` установить:

```php
'enabled' => false,
```

После обновления формы это выключит и показ новых правил, и добавление инструкции в новые задачи. Существующие поля продолжат работать.

Не удалять `service_rules.php`, пока новый `class.php` подключает его через `require`. Для полного отката сначала восстановить сохранённые `class.php` и `script.js`, затем убрать новые PHP и CSS, обновить ресурсы страницы.

## Основа и проверка

Исходные `class.php` и `script.js` восстановлены из предыдущего архива и его `changes.diff`; с учётом исходных переводов строк CRLF контрольные суммы совпали с ранее присланными `class(1).php` и `script(1).js`. Они приведены в `source_sha256.txt`.

Разметка правой колонки проверена по ранее приложенному `template(1).php`. Новый блок располагается вне обёртки с фиксированной высотой, поэтому раскрытие инструкции не требует менять высоту описания услуги.

Подробности локальной проверки приведены в `validation.md`. `preview.html` — автономный макет с фактическим JavaScript и CSS из комплекта и имитацией окружения Bitrix. Оформление остальной страницы приближено к предоставленному скриншоту: актуальный штатный CSS портала отсутствует. Макет ничего не отправляет на портал.
