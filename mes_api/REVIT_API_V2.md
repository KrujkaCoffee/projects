# Revit ERP API v2

Модуль `revit_router.py` реализует серверную часть контракта клиента Revit 2022 и
сохраняет совместимость с legacy-полями `Stage`, `ErpCode`, `Unit`, `Quantity`.

## Реализованные операции

- `POST /api/v1/revit/nomens`:
  - `action=get_nomenclature_list` — номенклатура выбранного вида;
  - `action=search_nomenclature` — глобальный поиск по коду, наименованию,
    полному наименованию и артикулу;
- `POST /api/v1/revit/resource/validate/` — проверка payload v1/v2;
- `POST /api/v1/revit/resource/create/` — повторная защита и создание ресурсной;
- `POST /api/v1/revit/nomens/bycodearray/` — пакетное получение наименований;
- прежние маршруты дерева, справочников, создания номенклатуры и проверки ссылки.

Глобальный поиск ограничивает `limit` диапазоном 1–500 и `offset` диапазоном
0–1500. Результаты поиска кешируются на 30 секунд, содержимое выбранного вида —
на 60 секунд, редко меняющиеся справочники — на 10 минут. После создания
номенклатуры соответствующие кеши очищаются.

## Проверка ресурсной

Для `contract_version=2` сервер требует:

- `action=upload_resource_map`;
- объект `schedule` с именем спецификации;
- `match_state=matched` и непустой `element_ids` у каждой экспортируемой строки;
- положительное количество и ERP-код;
- одинаковый ERP-код у визуально неразличимых строк с одним набором `ElementId`.

Одна операция принимает до 10 000 строк ресурсов.

Ошибки строк возвращают одновременно порядковый `row` и исходный
`source_row` Revit. Количество принимает как число, так и отображаемую строку
вида `1 234,50 м`.

Коды основного изделия и всех материалов проверяются одним запросом к 1С на
каждые 200 уникальных кодов. Успешная проверка payload кешируется на 120 секунд:
следующий `resource/create` с тем же телом не повторяет проверочные запросы. При
прямом вызове `resource/create` без предварительной проверки API выполняет её
самостоятельно.

После пакетной проверки создание не повторяет поиск основного изделия и не
перечитывает уже инициализированную статью калькуляции.

Материалы группируются по значению `stage`; порядок этапов и строк сохраняется.
HTTP-вызовы к 1С ограничены таймаутами подключения/чтения.

## Конфигурация

База 1С пока сохраняет принятое для этого маршрутизатора значение `ERP_MES1`.
Для HTTP-сервиса создания номенклатуры можно переопределить учётные данные:

```text
ERP_HTTP_USER
ERP_HTTP_PASSWORD
ERP_ODATA_USER
ERP_ODATA_PASSWORD
```

Если переменные не заданы, используется существующая конфигурация
`project_cust_38.api_erp_commands`.

## Проверка перед выкладкой

1. Запустить тесты:

   ```bash
   python -m unittest discover -s mes_api/tests -v
   ```

2. Проверить глобальный поиск минимум по трём вариантам:

   - точный код `00-00179666`;
   - часть наименования `труба 108`;
   - артикул существующей номенклатуры.

3. На payload с 74–200 строками проверить в журнале запись
   `пакетная проверка кодов`: для не более чем 200 уникальных кодов значение
   `requests` должно быть `1`.
4. Отправить строку с несуществующим кодом и убедиться, что ответ `400` содержит
   её реальный `source_row`.
5. Выполнить штатную последовательность `validate` → `create` и убедиться, что
   пакетная проверка кодов не запускается второй раз.
6. Открыть возвращённую `e1c://` ссылку и проверить состав материалов, суммы
   количеств и разбиение по этапам.

Полноценная приёмка требует соединения с `ERP_MES1`: локальные тесты не исполняют
язык запросов 1С и не создают реальный объект ресурсной спецификации.

## Доработки после приёмки — 27.09.2026

Порядок обновления: сначала API, затем DLL плагина. Старые клиенты продолжают
работать с новым API. Новый клиент требует endpoint статей калькуляции.

### Частичная выгрузка

В оба тела `resource/validate/` и `resource/create/` добавлено поле
`skip_unmapped_rows` (JSON boolean, по умолчанию `false`). Новый клиент перед
созданием спрашивает: «Не заполнен код 1C-ERP у N строк номенклатуры. Эти строки
не попадут в ресурсную спецификацию. Продолжить?» Отказ отменяет отправку.
Кнопка «Проверить» проверяет заполненные строки и показывает предупреждение;
она не заменяет подтверждение при последующей выгрузке.

При `true` исключаются только строки с пустым кодом / пробелами / `-`.
Заполненный, но некорректный или неизвестный код остаётся ошибкой. Проверки
количеств и связи с ElementId применяются ко всем экспортируемым строкам.
Если после исключения строк не осталось, создание блокируется.
Полный снимок `schedule.body_rows` и оригинальные номера `row/source_row`
сохраняются; строки в модели Revit не удаляются и коды не меняются.

Успешный validate возвращает `validated_rows`, `exported_rows`, `skipped_rows`,
`skipped_source_rows` и `warnings`. Create сохраняет прежний ответ 1С и добавляет
`export_summary` с тремя последними числовыми/списочными показателями.
Признак пропуска и статья входят в отпечаток проверенного payload. Прямой
create и create после validate используют одинаковое исключение строк.

### Статья калькуляции

`POST /api/v1/revit/resource/cost_articles/`

```json
{"action":"get_cost_articles"}
```

Ответ: массив `{"Ref_Key":"UUID статьи","Description":"Наименование"}`.
Запрос параметризован ссылкой `Родитель` на `Справочники.СтатьиКалькуляции`:
`e566b3c1-019f-11e7-80c0-4ccc6a67082d`. Возвращаются непосредственные дети
родителя, без групп и помеченных на удаление записей. Кеш — 10 минут.

Новый клиент явно выбирает одну статью для всех материалов ресурсной и передаёт
`cost_article_ref` в validate/create. Сервер проверяет UUID и принадлежность
доступному списку. Клиентское название статьи не используется. Пустая или
чужая ссылка даёт `field_errors.cost_article_ref`. Отсутствующее поле / `null`
оставляет прежнюю статью только для обратной совместимости старых клиентов.

`Cust_resource_creator` получает выбранные UUID и наименование в
`ArticulationArticles`. Его существующий контракт с сервисом 1С передаёт
`Материалы_Статья_калькуляции` по наименованию. Поэтому при приёмке нужно
проверить фактически установленную статью в 1С; разрешение одинаковых названий
в разных группах зависит от обработчика на стороне 1С.

### Источник запроса видов и серверный фильтр

Оба адреса `POST /types` и `POST /types/` принимают:

```json
{"action":"get_classifier_tree","source":"main"}
```

Отсутствующий / пустой `source` соответствует `main`.
Новый плагин отправляет `revit_mapping` при сопоставлении материалов и
`revit_output_product` при подборе выпускаемого изделия. Без настройки все
контексты получают прежний набор видов. `/nomen/kind/form/` возвращает
перечисление **типов** номенклатуры; этот фильтр относится к дереву **видов**.

Настройка сервиса: переменная окружения `REVIT_NOMENCLATURE_FILTERS` с JSON:

```json
{
  "revit_mapping": {
    "include_refs": ["11111111-1111-1111-1111-111111111111"],
    "exclude_refs": ["22222222-2222-2222-2222-222222222222"]
  },
  "revit_output_product": {
    "include_refs": ["33333333-3333-3333-3333-333333333333"]
  }
}
```

UUID в примере — заглушки: заменить ссылками реальных видов/папок.
После изменения окружения перезапустить API и переоткрыть окно плагина.

- `include_refs` отсутствует / `null`: весь прежний каталог;
- `include_refs: []`: пустой каталог;
- непустой список: указанные виды/папки с потомками и необходимыми предками;
- `exclude_refs`: исключить указанные узлы со всеми потомками;
- без `exclude_refs` действуют прежние восемь исключений из API;
- `exclude_refs: []` явно отменяет прежние исключения для данного источника;
- неизвестный источник использует настройку `main`, затем встроенную;
- исключение приоритетнее включения; удалённые папки скрываются с потомками.

В кеше хранится исходное дерево, фильтр применяется отдельно для каждого
источника, поэтому результаты разных окон не смешиваются. Ошибочная настройка
возвращает 503. Это настройка отображения дерева: глобальный поиск и проверка
уже назначенных кодов ею не ограничиваются, механизмом прав доступа она не является.

### Проверка новых сценариев

Установить `fastapi` и `httpx` в тестовое окружение, выполнить из корня:
`python -m unittest discover -s mes_api/tests -v`.
Без этих зависимостей HTTP-тесты будут явно пропущены.

1. Две строки с кодами и одна без: validate предупреждает, create с `true`
   создаёт только две; без флага возвращает 400. Сверить `skipped_source_rows`.
2. Все коды пусты; неверный заполненный код; отрицательное количество;
   неоднозначный ElementId — каждый сценарий должен блокировать создание.
3. Получить справочник статей, выбрать две разные статьи в двух пробных
   ресурсных и сверить статью у всех материалов в 1С. Проверить неподходящий UUID.
4. Выполнить validate → create и прямой create: состав должен совпасть.
5. Настроить разные фильтры двум источникам, включая вложенные папки;
   проверить, что предки видны, соседние виды не возвращаются, кеш не смешивает ответы.
